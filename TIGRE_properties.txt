TIGRE RECONSTRUCTION ALGORITHMS - COMPLETE REFERENCE
================================================================================

This document describes all reconstruction algorithms available in TIGRE,
including their input arguments, optional parameters, and outputs.


All TIGRE reconstruction algorithms share these MANDATORY arguments:

1. projections (np.array, dtype=float32)
   - Shape: (n_angles, detector_rows, detector_cols)
   - Description: Normalized projection data (-log(I/I0))
   - Note: Must be in TIGRE format (angles first dimension)

2. geo (tigre.geometry object)
   - Description: Complete geometry specification
   - Contains: All detector and volume properties

3. angles (np.array, dtype=float32)
   - Shape: (n_angles,) or (n_angles, 3)
   - Units: radians
   - Description: Rotation angles for each projection
   - Example: np.linspace(0, 2*np.pi, 360, endpoint=False)

4. niter (int) - FOR ITERATIVE ALGORITHMS ONLY
   - Description: Number of iterations to run
   - Typical range: 20-100 iterations
   - Note: Not used for FDK (direct method)

COMMON OUTPUT:

All algorithms return:
- volume (np.array, dtype=float32)
  - Shape: (geo.nVoxel[0], geo.nVoxel[1], geo.nVoxel[2])
  - Units: Linear attenuation coefficient (mm^-1)

Some iterative algorithms can also return:
  - error_metrics (list or array)
  - Description: Quality metrics computed at each iteration
  - Only if requested via optional parameters



--------------------------------------------------------------------------------
algs.fdk() - Feldkamp-Davis-Kress Algorithm
--------------------------------------------------------------------------------
Fast, direct reconstruction method for cone-beam CT. Based on filtered
backprojection. Best for high-quality, well-sampled data.

 volume = algs.fdk(projections, geo, angles, **kwargs)

MANDATORY ARGUMENTS:
  - projections: projection data (n_angles, rows, cols)
  - geo: geometry object
  - angles: rotation angles in radians

OPTIONAL ARGUMENTS (**kwargs):
  - filter (str): Reconstruction filter type
    Options: 'ram_lak' (default), 'shepp_logan', 'cosine', 'hamming', 'hann'
    Effect: Different trade-offs between sharpness and noise
    
  - parker_weight (bool): Apply Parker weighting for short scans
    Default: False
    Use when: Angular range < 360° (e.g., 200° scans)
    
  - verbose (bool): Print progress information
    Default: True

OUTPUT:
  - volume (np.array): 3D reconstructed volume
    Shape: (geo.nVoxel[0], geo.nVoxel[1], geo.nVoxel[2])

WHEN TO USE:
  - High-quality data with sufficient angular sampling
  - Fast reconstruction needed
  - No strong artifacts or noise issues
  - Full 360° rotation (or use parker_weight for short scans)

LIMITATIONS:
  - Sensitive to noise and artifacts
  - Requires well-sampled data
  - Limited ability to handle sparse/incomplete data

2. GRADIENT-BASED ITERATIVE ALGORITHMS (SART FAMILY)
================================================================================

--------------------------------------------------------------------------------
algs.sirt() - Simultaneous Iterative Reconstruction Technique
--------------------------------------------------------------------------------
Uses all projections simultaneously in each iteration. Slowest but most
stable convergence. Good for noisy data.

 volume = algs.sirt(projections, geo, angles, niter, **kwargs)

MANDATORY ARGUMENTS:
  - projections: projection data (n_angles, rows, cols)
  - geo: geometry object
  - angles: rotation angles in radians
  - niter (int): Number of iterations (typical: 50-100)

OPTIONAL ARGUMENTS (**kwargs):
  - lmbda (float): Step size multiplier (relaxation parameter)
    Default: 1.0
    Range: 0.1 - 2.0
    Effect: Larger = faster convergence but less stable
  - lmbda_red (float): Step size reduction factor per iteration
    Default: 0.99
    Range: 0.95 - 1.0
    Effect: Reduces step size over iterations for stability
  - Init (str): Initialization method
    Options: 'none' (default), 'FDK', 'multigrid'
  - InitImg (np.array): Custom initialization image
    Shape: Must match geo.nVoxel
  - verbose (bool): Print progress
    Default: True
  - computel2 (bool): Compute L2 error at each iteration
    Default: False
    Returns: (volume, l2_errors) instead of just volume
  - QualMeas (str or list): Quality metrics to compute
    Options: 'RMSE', 'CC', 'MSSIM', etc.
    Returns: (volume, quality_metrics)

OUTPUT:
  - volume (np.array): Reconstructed volume
  - errors (list): Optional, if computel2=True or QualMeas specified

WHEN TO USE:
  - Very noisy data
  - Need stable convergence
  - Time is not critical
  - Limited angular sampling

LIMITATIONS:
  - Very slow (uses all projections per iteration)
  - May require many iterations

--------------------------------------------------------------------------------
algs.ossart() - Ordered Subset SART
--------------------------------------------------------------------------------
Uses subsets of projections in each iteration. Much faster than SART
while maintaining good quality. Most popular choice for iterative
reconstruction.

 volume = algs.ossart(projections, geo, angles, niter, **kwargs)

MANDATORY ARGUMENTS:
  - projections: projection data (n_angles, rows, cols)
  - geo: geometry object
  - angles: rotation angles in radians
  - niter (int): Number of iterations (typical: 30-50)

OPTIONAL ARGUMENTS (**kwargs):
  - blocksize (int): Number of projections per subset
    Default: 20
    Range: 1 to n_angles
    Special cases: blocksize=1 (SART), blocksize=n_angles (SIRT)
    Typical: 10-20 for good speed/quality balance
  - OrderStrategy (str): How to order subsets
    Options: 'ordered', 'random', 'angularDistance'
    Default: 'angularDistance' (spreads angles evenly)
  - lmbda (float): Step size multiplier (relaxation parameter)
    Default: 1.0
    Range: 0.1 - 2.0
    Effect: Larger = faster convergence but less stable
  - lmbda_red (float): Step size reduction factor per iteration
    Default: 0.99
    Range: 0.95 - 1.0
    Effect: Reduces step size over iterations for stability
  - Init (str): Initialization method
    Options: 'none' (default), 'FDK', 'multigrid'
  - InitImg (np.array): Custom initialization image
    Shape: Must match geo.nVoxel
  - verbose (bool): Print progress
    Default: True
  - computel2 (bool): Compute L2 error at each iteration
    Default: False
    Returns: (volume, l2_errors) instead of just volume
  - QualMeas (str or list): Quality metrics to compute
    Options: 'RMSE', 'CC', 'MSSIM', etc.
    Returns: (volume, quality_metrics)

OUTPUT:
  - volume (np.array): Reconstructed volume
  - errors (list): Optional, if computel2=True or QualMeas specified

WHEN TO USE:
  - DEFAULT CHOICE for iterative reconstruction
  - Need balance between speed and quality
  - Moderate to good data quality
  - Most versatile algorithm

LIMITATIONS:
  - Can be sensitive to subset ordering
  - Requires tuning of blocksize

================================================================================
4. TOTAL VARIATION (TV) REGULARIZATION ALGORITHMS
================================================================================

These algorithms add total variation regularization to reduce noise while
preserving edges. Excellent for low-dose or sparse-angle CT.

--------------------------------------------------------------------------------
algs.asd_pocs() - Adaptive Steepest Descent POCS
--------------------------------------------------------------------------------
Minimizes total variation using Projection Onto Convex Sets (POCS).
Excellent for sparse-angle or low-dose CT. Preserves edges while
reducing noise.

 volume = algs.asd_pocs(projections, geo, angles, niter, **kwargs)

MANDATORY ARGUMENTS:
  - projections: projection data (n_angles, rows, cols)
  - geo: geometry object
  - angles: rotation angles in radians
  - niter (int): Iterations (typical: 30-100)

OPTIONAL ARGUMENTS (**kwargs):
  - alpha (float): TV regularization strength
    Default: 0.002
    Range: 0.0001 - 0.01
    Effect: Higher = smoother, more edge preservation
  - alpha_red (float): Reduction factor for alpha
    Default: 0.95
    Effect: Reduces regularization over iterations
  - rmax (float): Maximum allowed residual
    Default: 0.95 * ||projections||
    Effect: Constraint on data fidelity
  - epsilon (float): Edge threshold for TV
    Default: 1e-8
  - Init (str): Initialization method
    Options: 'none' (default), 'FDK', 'multigrid'
  - InitImg (np.array): Custom initialization image
  - verbose (bool): Print progress
    Default: True
  - computel2 (bool): Compute L2 error at each iteration
    Default: False

OUTPUT:
  - volume (np.array): Reconstructed volume (smoother, edge-preserving)

WHEN TO USE:
  - Sparse-angle data (few projections)
  - Low-dose, noisy data
  - Need edge preservation
  - Willing to accept longer computation time

LIMITATIONS:
  - Slower than non-TV methods
  - Requires parameter tuning (alpha)
  - Can over-smooth small features

================================================================================
6. ALGORITHM SELECTION GUIDE
================================================================================

DECISION TREE:

1. Do you have high-quality, well-sampled data?
   YES → Use FDK (fastest, excellent quality)
   NO → Continue to 2

2. Is your data sparse-angle (<180 projections) or very noisy?
   YES → Use TV algorithms (ASD-POCS, OS-ASD-POCS)
   NO → Continue to 3

3. Do you need fast reconstruction?
   YES → Use CGLS or OS-SART
   NO → Continue to 4

4. Need maximum quality with time available?
   → Use SIRT or OS-SART with many iterations

QUICK RECOMMENDATIONS:

For most cases: 
  algs.fdk() or algs.ossart()

For sparse/noisy data:
  algs.os_asd_pocs()

For large datasets:
  algs.cgls()

For low-dose CT:
  algs.os_asd_pocs() or algs.sart_tv()

================================================================================
7. PARAMETER TUNING GUIDELINES
================================================================================

ITERATION COUNT (niter):
- FDK: N/A (direct method)
- CGLS/LSQR/LSMR: 15-30 iterations
- SART/OS-SART: 30-60 iterations
- SIRT: 50-100 iterations
- TV methods: 50-100 iterations

RELAXATION (lmbda):
- Start with 1.0
- Increase (1.5-2.0) for faster convergence (less stable)
- Decrease (0.5-0.8) for more stable convergence (slower)

SUBSET SIZE (blocksize):
- Smaller (5-10): More stable, slower
- Medium (15-20): Good balance (RECOMMENDED)
- Larger (30-50): Faster, less stable

TV REGULARIZATION (alpha):
- Low noise: 0.0001-0.001
- Medium noise: 0.001-0.005
- High noise: 0.005-0.02
- Start small and increase until acceptable smoothness

INITIALIZATION:
- Most algorithms: 'none' (start from zeros)
- If slow convergence: Try 'FDK'
- TV methods: Often benefit from FDK initialization

================================================================================
8. OUTPUT INTERPRETATION
================================================================================

VOLUME UNITS:
- Linear attenuation coefficient (mm^-1)
- To convert to Hounsfield Units (HU):
  HU = 1000 × (μ - μ_water) / μ_water
  where μ_water is measured from water calibration phantom

TYPICAL VALUE RANGES:
- Air: ~0
- Soft tissue: 0.015-0.025 mm^-1
- Bone: 0.030-0.050 mm^-1
- Metal: >0.100 mm^-1

NEGATIVE VALUES:
- Small negatives (<1% of max) in background: Normal
- Large negatives or throughout image: Problem!
  Possible causes: Wrong I0, bad center-of-rotation, geometry error

================================================================================
10. TROUBLESHOOTING
================================================================================

PROBLEM: Reconstruction is blank/empty
SOLUTION: Check geometry (especially offDetector), verify projection data
          range, ensure angles are correct

PROBLEM: Ring artifacts
SOLUTION: Check center-of-rotation calibration (offDetector), verify detector
          pixel size, try TV regularization

PROBLEM: Blurry reconstruction
SOLUTION: Check voxel size (may be too large), increase iterations, try
          different filter for FDK

PROBLEM: Too much noise
SOLUTION: Use TV regularization (ASD-POCS, OS-ASD-POCS), increase alpha,
          more iterations, or try SIRT

PROBLEM: Over-smoothed
SOLUTION: Reduce TV alpha, fewer iterations, try SART instead of SIRT

PROBLEM: Reconstruction too slow
SOLUTION: Use FDK, reduce niter, increase blocksize, reduce voxel count,
          try CGLS instead of SART

PROBLEM: Out of memory
SOLUTION: Reduce geo.nVoxel (larger voxels), increase downsampling, crop
          projections more, use smaller blocksize
